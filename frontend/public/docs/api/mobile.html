Register this phone for banners

POST/api/v1/me/devices

After sign-in, with the app's push token. Banners: a new ticket for you, a mention, a customer reply, a Cevanos chat waiting for Accept; they name the ticket's number only. The same token again just refreshes it (or moves it to you, if whoever used this phone signed out). You keep your 10 newest phones. Banners stop when this sign-in ends (sign-out, a password change or reset, deactivation). 409: the phone is registered to someone still signed in on it. Not with an API key (403).

Reply from the mobile app

POST/api/v1/tickets/{ticket_id}/mobile-reply

On a chat handover nobody has accepted, accepts it first (line '<you> joined the chat (mobile)'), so the customer hears a person joined; a second tap that finds it just accepted replies all the same. If the reply then fails, the accept stands and the error says so. A light agent's text is saved as a private note instead (the chat stays waiting). Idempotency-Key is honoured.

Parameters

NameInTypeDescription
ticket_id requiredpathstring (uuid)
Idempotency-Keyheaderstring or nullOptional, any unique string (a UUID is good), up to 255 characters. Send the same key when you retry: a repeat returns what the first request made (header Idempotent-Replayed: true) instead of making it twice. The same key with a different request is 422. Keys last 24 hours, per member.

Request body (JSON)
