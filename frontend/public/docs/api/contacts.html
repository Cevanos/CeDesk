Import customers from a CSV file: dry run, then run (Admin; audited)

POST/api/v1/contacts/import

The request body is the file itself (UTF-8 CSV with a header row), not a form. At most 2 MB (413) and 5000 rows. mapping (JSON) says which column holds what: email (required), name, phone, organization, vip (true/false, yes/no, 1/0) and attributes (field key to column). Without it, columns are matched by name; the answer shows the mapping used. Matched by email (also merged-in addresses): a new address makes a customer; an existing one is changed by on_existing. A row that can't be read is listed by line and left out. dry_run=true (the default) writes nothing: send the same file with dry_run=false to import. The whole file is written in one go or not at all.

Parameters

NameInTypeDescription
dry_runquerybooleantrue: check only, write nothing.
on_existingqueryenumAn existing customer: fill_blanks sets only what it has no value for; overwrite sets every value the row has (an empty cell never clears one); skip leaves it.
mappingquerystring or nullJSON, e.g. {"email": "E-mail", "name": "Full name", "attributes": {"plan": "Plan"}}.

Request body

The file itself, not a form. See the description.

Responses
