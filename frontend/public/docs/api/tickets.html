One change on up to 100 tickets, each checked on its own

POST/api/v1/tickets/bulk

Each ticket is changed exactly as PATCH /tickets/{id} would change it (same rights, team scope, rules, SLA, events and history lines), in its own transaction: a ticket that fails is listed with its error and never stops or undoes the others. The answer is 200 even when some (or all) failed: read results. At most 10 bulk requests a minute per person (429).

Request body (JSON)

FieldTypeDescription
ticket_ids requiredlist of string (uuid)1-100 tickets; repeats count once.
action requiredenumassign (assignee_id), set_team (team_id), set_status (status), set_priority (priority), add_tags / remove_tags (tags), snooze (until), unsnooze. One of: assign, set_team, set_status, set_priority, add_tags, remove_tags, snooze, unsnooze
assignee_idstring (uuid) or nullassign: null unassigns.
team_idstring (uuid) or nullset_team: null clears the team.
statusenum or null
priorityenum or null
tagslist of string or null
untilstring (date-time) or nullsnooze: as POST .../snooze.

POST/api/v1/tickets/{ticket_id}/followers

Followers are told about public replies and status changes. Adding someone already following changes nothing. Adding someone else needs the right to change the ticket; they must be active and able to see it.
