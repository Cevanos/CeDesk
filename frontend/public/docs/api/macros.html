Add a macro; it goes last in the menu (Admin)

POST/api/v1/macros

Request body (JSON)

FieldTypeDescription
name requiredstring
steps requiredlist of objectRun in order. Each is one of: {"kind": "reply", "text": "Hi {{customer.first_name}}, ..."} (placeholders are filled when it runs); {"kind": "note", "text": "..."}; {"kind": "set_status", "status": "resolved"}; {"kind": "set_priority", "priority": "low"}; {"kind": "set_type", "type_id": "...", "only_if_empty": false} (fields the new type lacks are cleared); {"kind": "set_team", "team_id": "..."} (re-routes the ticket); {"kind": "add_tag", "tag": "refund"}. At most one reply and one note.
curl -X POST "$CEDESK_URL/api/v1/macros" \
  -H "Authorization: Bearer $CEDESK_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "name": "string",
  "steps": [
    {}
  ]
}'

Run a macro on a ticket: all its steps in one go

POST/api/v1/tickets/{ticket_id}/macros/{macro_id}

Steps run in order in one transaction; if one is refused, nothing is saved. Light agents get 403; an unaccepted handover gets 409.

Parameters

NameInTypeDescription
ticket_id requiredpathstring (uuid)
macro_id requiredpathstring (uuid)
If-Matchheaderstring or nullThe ETag from reading the ticket. 409 if the ticket changed since.
Idempotency-Keyheaderstring or nullOptional, any unique string (a UUID is good), up to 255 characters. Send the same key when you retry: a repeat returns what the first request made (header Idempotent-Replayed: true) instead of making it twice. The same key with a different request is 422. Keys last 24 hours, per member.

Example

curl -X POST "$CEDESK_URL/api/v1/tickets/{ticket_id}/macros/{macro_id}" \
  -H "Authorization: Bearer $CEDESK_KEY"
