Email: threaded under the earlier emails, to the same addresses. Slack: another message in the same thread.

Slack's Events API (the Slack side conversations app's Request URL)

POST/api/v1/slack/events/{workspace_id}

Public, for Slack only: every request must carry Slack's signature (X-Slack-Signature, X-Slack-Request-Timestamp, at most 5 minutes old), made with this workspace's signing secret, or it is refused before anything is read. Answers the URL check's challenge; a person's reply in a side conversation's thread is saved on it.

Parameters

NameInTypeDescription
workspace_id requiredpathstring (uuid)

Example

curl -X POST "$CEDESK_URL/api/v1/slack/events/{workspace_id}" \
  -H "Authorization: Bearer $CEDESK_KEY"

Responses

CodeMeaningBody
200Successful Responseobject
401Not signed by this workspace's Slack app
422Validation ErrorHTTPValidationError

Start a side conversation by email

POST/api/v1/tickets/{ticket_id}/side-conversations

Sent from the ticket's support address by the worker. Their reply comes back here (matched by the email's reply headers), the assignee is told (notification side_reply), and the customer sees none of it. The ticket gets a system line.

Start a side conversation in a Slack channel

POST/api/v1/tickets/{ticket_id}/side-conversations/slack

Needs the Slack side conversations app. Its bot posts your message in the channel (invite it there first) with the ticket's number and subject, never the customer's messages. Replies in that thread come back here and the assignee is told (notification side_reply). The customer sees none of it. The ticket gets a system line.

Parameters

NameInTypeDescription
ticket_id requiredpathstring (uuid)

Request body (JSON)

FieldTypeDescription
