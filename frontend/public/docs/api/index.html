API reference

Everything CeDesk does is available over HTTP. This reference is generated from the API description, so it always matches the code. Every path starts with /api/v1.

Signing in

Send a bearer token in the Authorization header. Use the token from POST /api/v1/auth/sign-in, or an API key that starts with cdk_. An Admin makes keys under Settings. A key acts as the Admin who made it, within its level.

curl "$CEDESK_URL/api/v1/tickets" -H "Authorization: Bearer $CEDESK_KEY"

Errors

A refused request answers with a 4xx code and a JSON body that has an error code and a message you can show to a person. 422 means the request is not valid, 429 means slow down (read Retry-After), and 401 or 403 mean you are not signed in or not allowed.

Retries and idempotency

Routes that create things accept an Idempotency-Key header. Send the same key when you retry and you get what the first request made, not a second copy.

Paging

Lists return next_cursor. Send it back as cursor, with the same filters, for the next page.
